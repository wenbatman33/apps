# 三國爭鋒 v2 重建規劃

> 定案日期：2026-08-13
> 目標：以 State.io 的操作手感為核心，疊加**武將系統**與**軍師策略**，做成一款順手、有決策深度的休閒即時策略。
> 舊程式碼（codex 版）整包封存到 `legacy/`，不刪除；新程式碼從零寫，**只沿用素材與路徑資料**。

---

## 一、為什麼要重寫，而不是繼續修

舊版的問題不是參數沒調好，是**核心模型太重**：

| 舊版做法 | 造成的問題 |
|---|---|
| 每個士兵有 HP／攻擊力／射程／冷卻／兵種相剋 | 632 行的戰鬥模擬，玩家完全看不出誰打贏誰、為什麼輸 |
| 城寨有 HP、完整度、修復進度、駐軍上限、共享募兵額度 | 五套數值互相牽制，任何調整都會連鎖爆掉 |
| 出兵有冷卻、單波上限、行軍鎖、自動重複派兵 | 玩家下的指令跟畫面發生的事對不起來（主城被自動抽乾＝「莫名掉血」的真兇） |
| 城寨只能派給相鄰城寨 | 沒有規劃感，只剩來回點擊 |

State.io 之所以順，是因為它只有**一個數字、一條路、一個動作**。v2 要先把模型砍到這個程度，再往上加深度。

## 二、核心玩法（State.io 模型）

### 2.1 城寨（節點）

每座城寨只有一個可見數字：**駐軍數**。

- **中立城寨**：不生產，站著等你來打（強化「搶地盤」動機）
- **已佔領城寨**：每 `1 / rate` 秒 +1，直到上限
- **等級 1／2／3**：等級決定生產速度與上限

| 等級 | 生產速度 | 駐軍上限 | 升級費用 |
|---|---|---|---|
| Lv1 | 0.55 兵/秒 | 30 | — |
| Lv2 | 0.85 兵/秒 | 50 | 25 兵 |
| Lv3 | 1.20 兵/秒 | 80 | 45 兵 |

- **主城**開局 Lv2、駐軍 25；被攻下即戰敗
- 升級操作：點自己的城寨 → 城寨上方浮出「⬆ 升級 25」按鈕 → 再點一次確認。**這是除了出兵以外的第二個決策軸**

### 2.2 出兵（唯一的主動操作）

- **拖曳**：按住我方城寨 → 拖到目標 → 放開，派出**駐軍的 50%**
- **點選**：點我方城寨 → 點目標，效果相同（PC 滑鼠與手機都走同一條路徑）
- **多選**：可連點多座我方城寨累加選取，或框選拖過去；再點一次目標 → **全部同時出兵**
- **雙擊目標**：傾巢而出（派 100%），給孤注一擲用
- **無冷卻、無單波上限、無行軍鎖**
- 目標**不限相鄰**：自動沿最短路徑行軍

### 2.3 行軍與戰鬥（極簡）

- 士兵沿路徑點以**串流**出發（每 0.08 秒放一個），視覺上是一條連續行軍隊伍
- **路上對撞**：敵我士兵在路上相遇，1 換 1 同歸於盡（State.io 的招牌手感）
- **抵達敵方／中立城**：駐軍 −1；駐軍降到 0 以下 → **換手**，剩餘兵力成為新駐軍
- **抵達我方城**：駐軍 +1
- **經過我方城**：直接通過，不停留
- 沒有 HP、沒有射程、沒有兵種相剋 —— 差異化全部改由**武將**提供

### 2.4 勝負

- 攻下敵方主城 → 勝；主城被攻下 → 敗
- 時限 **120 秒**；時間到時比較「城寨數 → 總兵力」判定
- 目標單場 90～150 秒，適合一局一局刷

## 三、武將系統

出戰前從五名武將中**選三名**帶上場。武將是**可移動的 buff 棋子**，永遠站在某座城寨上。

| 武將 | 定位 | 效果（駐守所在城寨時生效） |
|---|---|---|
| **關羽** | 鎮守 | 敵軍每 **2 兵**才能扣本城 1 兵 —— 守城核心 |
| **張飛** | 衝陣 | 從本城出兵時，該波移動速度 **+60%**，路上對撞 **1 換 2** |
| **趙雲** | 突襲 | 主動技：單騎直取任一連通城寨，抵達瞬間扣目標 **8 兵**（冷卻 20 秒） |
| **馬超** | 西涼鐵騎 | 本城生產速度 **+50%** |
| **黃忠** | 百步穿楊 | 每秒射殺 **1 名**經過本城道路的敵軍 |

**操作**：點下方武將頭像 → 點目標城寨 → 武將沿路移防（**需要行軍時間，不是瞬移**，這是取捨的來源）。

**被攻下時**：武將不會死，自動撤退到最近的我方城寨 —— 休閒向，不製造挫折感。

## 四、軍師策略（孔明 vs 司馬懿）

- 戰鬥中累積 **計策值**：每秒 +1，每多持有一座城寨 +0.3/秒
- 滿 **100** 可施放，手牌隨時保持 **2 張**，用掉一張立刻補抽

| 策略卡 | 效果 |
|---|---|
| **火計** | 指定城寨，燒殺周圍敵軍 **12 人** |
| **拒馬** | 指定一條道路，封鎖 **6 秒**，敵軍無法通過 |
| **伏兵** | 指定我方城寨，下一波出兵敵 AI 看不見、不反應 |
| **急行軍** | 全體我方士兵速度 **+80%**，持續 8 秒 |
| **策反** | 指定敵方城寨，其 **30%** 駐軍當場倒戈 |
| **屯田** | 我方所有城寨立即 **+5 兵** |

敵方司馬懿使用同一套規則（計策值可見），施放前 1.5 秒有**預警提示**，讓玩家有反應機會。

## 五、技術架構

重寫的最大目的之一：**讓遊戲規則可以離開瀏覽器單獨跑**，這樣平衡性由模擬驗證，不必由你當 QA 手動試。

```
warRangers/
├── legacy/                 ← 舊 codex 程式碼整包封存（唯讀，不刪）
├── assets/                 ← 完全沿用（圖、路徑遮罩）
│   └── navigation/*.json   ← 沿用：節點座標與道路折線
├── src/
│   ├── core/               ← 純 JS，零 Phaser 依賴，node 可直接跑
│   │   ├── mapData.js      ← 讀 navigation JSON → 節點圖 + 路徑取樣
│   │   ├── state.js        ← 對局狀態機：城寨、串流、對撞、佔領、勝負
│   │   ├── heroes.js       ← 武將定義與效果結算
│   │   ├── tactics.js      ← 策略卡定義與結算
│   │   └── ai.js           ← 敵方決策（難度分級）
│   ├── view/               ← Phaser：只負責畫與輸入，不放規則
│   │   ├── BattleScene.js
│   │   ├── hud.js
│   │   └── devTools.js     ← D 鍵微調工具（全域偏好硬性要求）
│   └── layout.js           ← LAYOUT_PC / LAYOUT_MOBILE 版面表
└── scripts/
    ├── test_core.js        ← 規則單元測試
    └── sim_match.js        ← headless 跑 1000 場，輸出勝率與平均時長
```

**關鍵原則**：`core/` 不 import Phaser，`view/` 不寫規則。任何平衡調整先在 `sim_match.js` 驗證過再進遊戲。

## 六、版面（PC 與手機）

你最早回報的「PC 無法遊玩」，根因是 720×1560 直式畫布在寬螢幕被 FIT 壓成中間一條細長條。

- **手機／直式**：維持現在的 720×1280 地圖 + 上下 HUD
- **PC／橫式**：畫布改 1280×720，**地圖置中保持原比例**，左欄放武將列、右欄放策略卡與戰況，不再有兩側大片空白
- 依 `window.innerWidth / innerHeight` 自動選版面，切換視窗大小即時重排
- **DEV 微調工具（D 鍵）**：所有元件可拖曳、x/y/scale/字級/顏色滑桿、PC/Mobile 分別調整、一鍵匯出 JSON 給我 baked 進原始碼
